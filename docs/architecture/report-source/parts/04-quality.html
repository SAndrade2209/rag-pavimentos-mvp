3. Quality attributes

Priorities were confirmed on 2026-11-23. Terms follow the architecture characteristics in course material based on Richards and Ford (2025). The method keeps the list short and picks the few attributes that matter most; every ADR states which of them it gains and which it sacrifices (Section 7.2).

3.1 Priority levels

LevelMeaning
HighDrives architecture decisions. Every ADR states how it affects these. At most four.
MediumMet through simple, standard choices, without dedicated design effort.
Nice to haveOnly if it costs almost nothing, or a client requires it.
ConstraintPass or fail. Not ranked and not traded against other attributes.

3.2 Constraints

  • Data, backups and language model processing stay in the US (MVP). Other regions are out of the MVP.
  • The platform runs on any major cloud provider.

3.3 Ranked attributes

AttributePriorityWhy it mattersCost accepted
Security (authentication, authorization, client data isolation)HighUC-07: users see only the projects granted to them, and a user without access cannot sign in. UC-08: permissions are set per project. UC-09: only users with the Correct and delete permission change data. Several clients with government data share the platform, so one client must never see another's data.Every query and screen checks permissions, and there is more to test.
Data traceability (archivability and audit trail)HighUC-05: new survey years are added, and an existing section and year is reported, not overwritten. UC-06: the section view shows every survey year on the network, including years loaded through other projects. UC-09: corrected and deleted values are kept with who, when and why. UC-02 and UC-03 depend on that full history.More storage and a more involved data model than overwriting values.
Deployability and simplicityHigh"An MVP that deploys fast" (CLAUDE.md). Not tied to one use case: it decides how quickly UC-01 to UC-09 reach users. Favors few containers (modular monolith) and well-known technologies.Some parts may need rework if the platform grows well beyond the MVP.
RecoverabilityHighThe network history built through UC-05 and UC-09 exists only in the platform: clients cannot rebuild the corrections, their reasons, or the history merged across projects from their own files. UC-02, UC-03 and UC-06 depend on it. Minimum: automatic daily backups of the database and files, kept in a separate US location, with a restore tested.Low at this level; stricter targets cost more.
MaintainabilityMediumThe use cases will change after the first users. Met by clear modules and automated tests on the rules that matter most: permissions (UC-07, UC-08) and PCI history and corrections (UC-05, UC-09).Time spent writing tests.
Extensibility (data loading and language model)MediumUC-05: CSV now, client database exports, PDFs later. UC-01 to UC-04: the language model must be switchable between hosted and self-hosted. A replaceable interface is built only at these two points, where a second option is already planned.A little more design in two modules.
Performance (response time)MediumUC-01 to UC-04 return answers that include language model calls; UC-06 opens the project overview and section view. "Response times must be reasonable" (CLAUDE.md). A target is not defined yet.Caching and query tuning, if a strict target is set.
UsabilityMediumUC-06: project overview and section view, following the demo's display. UC-01 to UC-04: answers state the threshold, years and filters used, so engineers can check them. Users are pavement engineers and airport staff.Interface design and testing with users.
InteroperabilityMediumUC-05: PCI data come from CSV files and from client pavement management systems (export file or direct connection). UC-01 to UC-04: tables are downloadable.Mapping each client's column names to section, coordinates, PCI and year.
Localization (units)Nice to haveUC-04 uses a search radius, so distance units matter; the demo has a units switch (US). International clients are out of the MVP.Unit conversion in the location search and displays.
AccessibilityNice to haveNo use case requires it. Public agencies may require it in their solicitations; if a client does, it moves up.Interface work and checks.

3.4 Not optimized

Decisions do not spend effort on these:

  • Scalability to millions of users.
  • Multi-zone high availability.
  • On-demand elasticity.
  • Privacy beyond standard security, such as hiding data even from administrators.
