Appendix A. Glossary

TermMeaning in this report
Access guardThe component that checks every request to the API application and denies by default (ADR 7).
ADRArchitecture decision record: one decision with its context, options, the attributes it gains and sacrifices, and its consequences.
Answer templateFixed text for one query plan operation, filled with values from the query results or the validated plan (ADR 6).
Bronze, silver, goldThe three data layers of the platform database: loads as received; validated PCI with versions; serving tables (ADR 7).
C4 modelA way to describe software architecture at four levels of detail: context, containers, components and code (Simon Brown). This project uses the first three (ADR 1).
ClientAn agency or airport whose data the platform holds, isolated from other clients (ADR 3).
Column mappingThe saved link between a client's column names and section, coordinates, PCI and year (ADR 4).
Component (C4)A part of a container with one responsibility, such as the access guard or the query planner.
ConflictA loaded row for a section and survey year that already exist. The existing value stays and the load summary shows both (UC-05).
Container (C4)An application or data store: here the web application, API application, language model, platform database and file storage.
Funding agencyThe government agency that may fund development. Its pavement management system gets the automatic connection (ADR 4).
Gold refreshThe rebuild of a client's gold tables from silver, in the same database transaction as a load or correction (ADR 7).
Input adapterReads one source (CSV, Excel, the agency connection; PDFs later) into the internal format (ADR 4).
JudgeA model call that checks whether a query plan answers the question, before the query runs (ADR 6).
Load jobA retryable background job, in the same process, that runs an upload or a connection run (ADR 7).
M&RMaintenance and rehabilitation (UC-01).
MFAMulti-factor authentication (ADR 2).
Modular monolithOne deployable application split into modules by business area, each owning its tables (ADR 7).
OpenID ConnectThe sign-in standard between the platform and the identity service; the API accepts only signed sign-in tokens (ADR 2).
PCIPavement Condition Index, stored per section and survey year on a 0 to 100 scale (UC-05).
ProjectHow PCI data arrive and where they are shown. Access is granted per project (UC-08).
Query planA structured request built from filters and operations, validated by the API and turned into a parameterized query (ADR 6).
Retention periodHow long original files and answer log entries are kept before deletion; set with each client (ADR 7).
Reword checkThe API keeps the model's reworded answer only if it has the same numbers, survey years and section identifiers as the template text, in the same order (ADR 6).
Row-level securityA database feature that returns only the rows a policy allows; here, the rows of the requesting client (ADR 3).
SectionA pavement section of an airport or road network. PCI is recorded per section and survey year.
Single sign-onSigning in with the client organization's own accounts, for clients that require it (ADR 2).
Survey yearThe year of a PCI survey. Every survey year is kept; years without a survey are shown as gaps (UC-02, UC-06).
