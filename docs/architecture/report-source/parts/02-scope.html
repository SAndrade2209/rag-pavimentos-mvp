Part I. Drivers

1. Scope and constraints

The MVP is the first release of a pavement data platform, prepared as a proposal for a government agency that may fund its development. The goal is a platform that answers natural-language questions about tabular pavement data and shows the data in project and section views.

1.1 Phase 1 data

Phase 1 holds PCI (Pavement Condition Index) information only, from airport or road networks. Each record has four fields:

FieldUsed by
SectionUC-01 to UC-06, UC-09
CoordinatesUC-04 (location search); loaded in UC-05
PCIUC-01 to UC-06, UC-09
Year (survey year)UC-01 to UC-06, UC-09

Every load also carries the client the data belong to, because client data are isolated (UC-05).

1.2 In and out of the MVP

In the MVPOut of the MVP
  • Question answering over the PCI data. Answers are text and tables, without charts.
  • Project display as in the demo: project list and project workspace.
  • Project data overview: current PCI by section.
  • Section view: PCI by survey year, with years without a survey marked as gaps, and the survey timeline.
  • Sign-in, access by project and access management. Loading, correcting, deleting and granting access depend on the user's permissions on each project.
  • Corrections and deletions keep the old values, with who, when and why.
  • PDF documents and PDF extraction.
  • Public pavement data sources.
  • Network map and network view. Sections are reached from a project, not from a map.
  • Specifications.
  • Workbench: mix design, material characterization, pavement life prediction and construction acceptance tools.

PDFs and other file types come later, so loading PCI data must allow adding them without rework.

1.3 Network data, project access

PCI data belong to the airport or road network, not to the project. A project is how data arrive and where they are shown.

  • Each load comes in through a project (UC-05). The records are stored for the network section and survey year, and nothing is deleted when the project ends.
  • Every survey year is kept, for future analysis, evidence and later surveys.
  • The section view shows every survey year stored for the section on the network, including surveys loaded through other projects (UC-06).
  • Access is granted per project (UC-08). A user sees only the projects granted to them and, inside each one, the actions their permissions allow (UC-07).
