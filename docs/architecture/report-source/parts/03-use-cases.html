2. Use cases

Nine use cases describe what users need to resolve with the PCI data and the result they obtain, without implementation details. UC-01 to UC-06 answer a pavement question or serve the data. UC-07 to UC-09 are supporting use cases: they answer no pavement question, but the others depend on them.

2.4 Answer format (UC-01 to UC-04)

  • A short text answer plus the source rows.
  • A downloadable table.
  • Stated assumptions: the threshold, years and filters used.
  • No charts. Charts appear only in the UC-06 section view.

2.5 Use case details

UC-01Identify M&R candidate sections Main
ActorsPrimary: pavement management engineer; district/maintenance staff; airport pavement management staff. Secondary: Continuum consultant.
GoalList the sections in poor condition in the latest survey to build the maintenance and rehabilitation (M&R) work program.
Example"Which sections had a PCI below 55 in the latest survey?" The threshold (55) is an example given by the user in the question, not a recommended value.
DataSection, PCI, year.
Expected result
  • A short answer with the number of sections below the threshold.
  • A table of section, survey year and PCI, sorted from lowest PCI, with the source rows. Downloadable.
  • The answer states the PCI threshold and the survey year used.
  • If the question gives no threshold and none is configured, the system asks the user for one before answering.
UC-02Track PCI over time Main
ActorsPrimary: pavement management engineer; airport pavement management staff. Secondary: Continuum consultant.
GoalSee how a section or a set of sections deteriorated between surveys, to time M&R and support condition reports.
Examples"How has the PCI of section X changed since 2018?" "Which sections lost the most PCI points since the previous survey?" The year (2018) is an example.
DataSection, PCI, year.
Expected result
  • PCI for each survey year and the change in PCI points between surveys, with the source rows.
  • A table of section, survey year, PCI and change in PCI points. Downloadable.
  • The answer states the years compared.
  • The answer notes the years in which a section has no survey, instead of filling the gap.
UC-03Summarize network condition for budget and reporting Main
ActorsPrimary: pavement management engineer; airport pavement management staff.
GoalProduce network-level condition figures for funding requests and condition reports.
Examples"What was the average PCI of the network in each survey year since 2020?" "How many sections were below the threshold in 2024 compared with 2022?" The years are examples.
DataSection, PCI, year.
Expected result
  • Averages or counts by survey year, with the table they were computed from. Downloadable.
  • The answer states that averages are by section count, not weighted by area or length, because those fields are not in the phase 1 data.
  • For counts below a threshold, the answer states the threshold used (same rule as UC-01).
UC-04Find sections by location to plan inspections Main
ActorsPrimary: district/maintenance staff; airport pavement management staff.
GoalFind sections near a point or inside an area, with their latest PCI and last survey year, to decide which sections to survey next or which records to verify.
Example"Which sections within 2 km of these coordinates have not been surveyed since 2021?" The radius (2 km) and the year (2021) are examples.
DataSection, coordinates, PCI, year.
Expected result
  • A table of section, latest PCI, last survey year and distance from the point. Downloadable.
  • The answer states the search radius and the coordinates used.
UC-05Load PCI data Main
ActorsPrimary: pavement management engineer; airport pavement management staff; client data administrator (a separate client role; the role name is a placeholder). Secondary: Continuum consultant, loading data on the client's behalf. Each needs the Load permission on the project; Continuum consultants get project access like any other user (UC-08).
GoalLoad a client's PCI data so that UC-01 to UC-04 can answer from it and UC-06 can show it, and add new survey years as they become available.
Examples"Load the 2025 PCI survey for this airport from this CSV file." "Load the latest PCI records from our pavement management database." The year (2025) is an example.
DataSection, coordinates, PCI, year, and the client the data belong to.
SourcesCSV and Excel (.xlsx) files uploaded through the web application. For the funding agency only, an automatic connection to its existing pavement management system; ADR 4 leaves the connection method to a separate ADR.
Expected result
  • New survey years are added. Existing survey years are kept.
  • A section and year that already exist are a conflict: the existing value stays, and the load summary shows both values. A user with the Correct and delete permission can accept the new value as a correction (UC-09), with a reason.
  • A load summary: rows added, conflicts, rejected rows with the reason for each, and column mapping problems.
  • If a load fails, it can be run again without duplicating data.
  • [assumption] A row is rejected if section, PCI or year is missing, or if PCI is outside the 0 to 100 scale.
  • Data loaded for one client are visible only to that client's users.
  • Each load comes in through a project. The PCI records are stored for the airport or road network and kept for every survey year. Nothing is deleted when the project ends.
  • Corrections and deletions of loaded data go through UC-09.
UC-06View PCI data in a project Main
Actors[assumption] Primary: pavement management engineer; airport pavement management staff; district/maintenance staff. [assumption] Secondary: Continuum consultant.
GoalSee the current PCI of the sections in a project, and the PCI history of one section, without writing a question.
Examples"Open the PCI data of this project." "Open section X." Section X is a placeholder.
DataSection, PCI, year.
Expected result
  • Only projects the user has access to are shown (UC-07). Requires the View permission.
  • Project data overview: a table of the project's sections with the latest PCI and the survey year of that PCI.
  • Section view, opened from the overview: PCI by survey year as a chart, with years without a survey marked as gaps, not filled; and the survey timeline, showing when each PCI survey of the section was done.
  • The section view shows every survey year stored for the section on the network, including surveys loaded through other projects.
UC-07Sign in and open accessible projects Supporting
ActorsEvery user of the platform: the eight roles in C1 (Section 5).
GoalSign in and work only with the projects the user has been granted.
Example"Sign in and open my projects."
DataThe user's identity; the projects granted to the user and the user's permissions on each one (UC-08).
Expected result
  • Users sign in through the identity service, with multi-factor authentication: a platform account, their organization's own account (single sign-on, for clients that require it), or, for Continuum staff, their Google Workspace account.
  • After sign-in, the project list shows only the projects granted to the user.
  • A user without access to any project cannot sign in.
  • Opening a project that was not granted is refused.
  • Inside a granted project, the available actions match the user's permissions on that project.
UC-08Manage project access Supporting
ActorsClient manager; project lead; Continuum administrator. [assumption] Scope of each in 2.3.
GoalGive a person access to a project, set what they can do in it, and remove that access when it is no longer needed.
Examples"Give this engineer View and Load permissions on project X." "Remove this person's access to project X." Project X is a placeholder.
DataThe person; the project; the permissions (View, Load, Correct and delete, Manage access).
Expected result
  • The person can open the project, with only the actions their permissions allow (UC-07).
  • Removing access stops the person from opening the project.
  • [assumption] The PCI data the person loaded stay in the platform after their access is removed.
  • [assumption] Each grant or removal records who made it and when.
UC-09Correct or delete PCI data Supporting
ActorsAny user with the Correct and delete permission on the project (UC-08).
GoalFix a wrong PCI value, or remove records loaded by mistake, without losing the record of what was there before.
Examples"Change the 2024 PCI of section X from 85 to 58; the digits were swapped when the data were entered." "Remove the rows from yesterday's load; the file belonged to another airport." The values and section X are examples.
DataSection, year and PCI of the record to correct or delete; the reason for the change.
Expected result
  • From then on, answers (UC-01 to UC-04) and views (UC-06) use the corrected value.
  • The old value, or the deleted record, is hidden from views and answers but kept, with who made the change, when and why.
  • [assumption] The change history of a section can be viewed.
