9. Superseded decisions

Two ADRs were replaced on 2026-11-23. Both stay in the repository with the status "Superseded by" and a link to the replacement. Query plans built from blocks, the seven modules and the bronze, silver and gold layers carried over.

Superseded ADRReplaced byWhat changed
Ground answers in PCI data through validated query plans
2026-11-23-ground-answers-with-validated-query-plans.md		 ADR 6
  • Judge: now runs before the query, and a rejected plan goes back to the planner with the reason, up to three plans. Before, it ran after the query with no action defined on rejection.
  • Answer text: now written by the API from one template per operation, then reworded by the model and kept only if numbers, survey years and section identifiers match. Before, the model wrote the text from the result rows, followed by a number check.
  • Data sent to the model: now the question, plans and template text, never result rows. Before, result rows were sent for the answer text.
  • Answer log: now kept for a retention period, then deleted. Before, kept like other data.
  • Model calls per answered question: now three to seven. Before, two or three.
Structure the backend as a modular monolith with bronze, silver and gold data layers
2026-11-23-backend-modular-monolith-with-data-layers.md		 ADR 7
  • Gold: now rebuilt in the same database transaction as each load or correction. Before, rebuilt after it.
  • Original files: now kept in file storage for a retention period and deleted by a scheduled retention job. Before, not decided, with file storage marked as an assumption.
  • Audit log: now PCI data changes, access grants and removals, denied requests, load summaries and the answer log; allowed requests are not logged one by one. Before, every access decision.
  • Option comparison: the chosen option F is now scored with options A to E. Before, it was not scored.
  • Load jobs: unchanged, with the reason now recorded: the initial load of a client's history may take longer than a web request allows.
