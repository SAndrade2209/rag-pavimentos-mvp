11. Cross-cutting views

Some properties come from several decisions at once. These tables collect them in one place, each row with the ADR or document it comes from.

11.1 Security, layer by layer

LayerWhat it doesSource
Identity serviceSigns users in with MFA (platform accounts), single sign-on, or Google Workspace with two-step verification. The platform stores no passwords and accepts only signed tokens. For single sign-on users, MFA is enforced by the client's own identity provider.ADR 2; UC-07
Access guardOn every request: checks the token, resolves user and client, loads project permissions, sets the client for row-level security and denies by default. A user without any project cannot sign in.ADR 7; UC-07
Per-project permissionsView, Load, Correct and delete, Manage access, granted per project. [assumption] The levels are an assumption in the use cases.Use cases; UC-08
Row-level securityThe database returns only the requesting client's rows, on every schema. The API also filters by client. Cross-client isolation tests are in the minimum automated test set.ADR 3; ADR 7
Read-only answeringThe question answering module has read-only database access, to gold only, with a row limit.ADR 6; ADR 7
Parameters, not codePlan values travel as parameters, never as code. Model-written queries are not in the first release.ADR 6
Model boundaryOne interface is the only way to reach the model. The model never reaches the database and never receives result rows; it receives the question, plans and template text.ADR 5; ADR 6
SecretsKeys for the language model, identity service and agency connection come from the cloud provider's secret manager, injected as settings when the application starts.ADR 7
Agency connectionRead-only access limited to PCI data; credentials outside the code; traffic and processing in the US.ADR 4
Audit logPCI data changes, access grants and removals, denied requests, load summaries and the answer log. Allowed requests are not logged one by one.ADR 7
